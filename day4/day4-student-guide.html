Stage 1

Refine the Idea

Watch how a vague sentence becomes a specification — then everyone takes the same one, so we all build the same thing.

Watch the demonstration

Laptops down for this part. Your facilitator runs the skill on this brief and answers its questions out loud:

> use the idea-refine skill on this: a small tool for Sunrise Bakery to track money coming in and going out, so the owner can see where they stand at the end of a day

Three things worth watching for:

  • It won't start writing. It asks questions first — the opposite of what people expect from AI.
  • It offers choices. Two or three directions, with a recommendation and a reason for it.
  • The Not Doing list. Good ideas, cut on purpose. This is what makes a build finishable.

Then everyone takes the same specification

Your facilitator's run took a few minutes, and yours would come out slightly different. So that everyone builds the same thing, you'll be given the finished one.

This isn't cheating

A real team agrees one specification and works from it. Twelve people each with a private version isn't how software gets built — it's how projects fail.

Two sections decide everything that follows

MVP Scope — what we build

One transaction record. Add it from a form. See them all in a table. A running balance. Delete a mistake.

Five things. That's the whole app.

Not Doing — what we refuse

No login. No editing. No category management. No charts. No deployment.

Every one a reasonable idea, cut on purpose.

When someone asks later "should we add a login?", the answer is already written down. That is what a Not Doing list is for.

Stage 2

Plan & Slice

Turning a specification into tasks — and the one decision about how to cut them up that changes everything.

Two ways to cut up the same work

By layer — the obvious way

1. Build the whole database
2. Build all the endpoints
3. Build the whole page
4. Connect it up

Run out of time at step 2 and you have a database and no application. Nothing works until everything works.

By feature — vertical slices

1. Make it run
2. Record a transaction
3. See it and the balance
4. Delete one

Run out of time at step 2 and you still have a tool that records money. Every step ends with something usable.

This idea travels well beyond software. It is also how you would plan a scheme of work — each week should leave students able to do something, not halfway through a topic.

Do nowTurn the specification into tasks
> use the planning-and-task-breakdown skill on docs/ideas/cash-flow-tracker.md. Slice vertically — each task must end with something I can open in a browser and use.
Why say "slice vertically" Left alone it may still plan by layer. Naming the shape you want is the difference — exactly like naming the file on Day 3.

Stage 3

Build It

Three tasks. One at a time, checked before the next one starts.

How the new skill works

Build a bit, check it works, then build the next bit. That's the whole of incremental-implementation. It sounds obvious — and it is the discipline almost everyone abandons the moment they are in a hurry.

The reason it matters: a mistake in task 2 makes tasks 3, 4 and 5 wrong, and you won't know which change caused it. Checking each piece is what keeps debugging small.

Worth knowing

Every one of these is an ordinary text file. Nothing is compiled and nothing breaks if you edit one. If the agent isn't behaving how you want, open the rules and change the wording — that is the whole mechanism.

Section 9

When something goes wrong

Today's problems are the ones that come up when building an app with a database.

What you seeWhat it meansWhat to do
EADDRINUSE / port in use The app is already running in another window. Press Ctrl + C in that window, or ask for a different port.
The page loads but the form does nothing The page can't reach the server. Say: "the form doesn't save anything — please check the page is calling the right address."
The balance looks wrong Usually the amounts aren't being added as numbers. Say: "the balance is wrong — please check how amounts are stored and added up."
My data disappeared after a restart It was never saved to the database. Ask it to confirm the record is actually written to cashflow.sqlite.
It tried to commit, or asked about git The build skill expects version control. Say "no git today". It's already excluded in AGENTS.md.
It's forgotten what we agreed The context window is full — see Day 3. /new, then point it at tasks/todo.md to pick up where you were.
429 / rate limit Too many tokens too quickly. Wait a minute, or switch to your spare key with /connect.
It started two tasks at once It got ahead of itself. Say: "stop — finish task 2 only, and let me check it before task 3."
The universal fix, one last time

For anything not on this list — copy the whole message and paste it to your agent, with a line saying what you were trying to do. You have never had to work these out alone, and you still don't.
